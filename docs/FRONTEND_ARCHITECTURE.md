# Site Shield AI — Frontend Architecture & Compliance Dashboard

## 1. Overview and Architectural Alignment

In alignment with the approved project architecture ([`docs/RAG_ARCHITECTURE.md`](file:///home/abhinivesh/Downloads/siteshield_ai/docs/RAG_ARCHITECTURE.md)) and product specifications, this document details the implementation of the **Site Shield AI Frontend Compliance Dashboard** (Gate 7).

The frontend delivers an assistive, safety-critical decision-support interface tailored for construction compliance engineers, quality inspectors, and project managers.

### Core Frontend Principles
1. **Separation of Concerns:** API communication, data transformation, and presentation are strictly segregated. All backend communication is routed through a dedicated API client layer ([`frontend/lib/api.ts`](file:///home/abhinivesh/Downloads/siteshield_ai/frontend/lib/api.ts)).
2. **Deterministic Source Inspection:** Claims generated by the RAG backend feature interactive inline citation badges (`[E1]`, `[E2]`). Clicking any citation badge immediately brings up the verbatim source chunk, hierarchy breadcrumbs, and provenance metadata in the Excerpt Inspector.
3. **Transparent Precedence & Conflict Alerting:** When the backend flags divergences between governing specifications and historical site inspection reports, or between revisions, a prominent legal precedence banner appears with side-by-side excerpt comparisons.
4. **Safety Abstention First-Class UI:** Insufficient regulatory evidence is treated as a critical safety event (`QueryStatus.ABSTAINED`). The UI surfaces clear explanations and actionable document upload guidance rather than leaving users in doubt.
5. **Realistic Demonstration Mode:** Includes three fully labeled demonstration scenarios (`[DEMONSTRATION DATA ONLY]`) covering grounded compliance, revision conflicts, and safety abstentions for testing and offline presentations without inventing real regulations.

## 4. Reusable Component Specifications

### 4.1 Navbar (`components/Navbar.tsx`)
- Displays brand identity (`Site Shield AI v0.1.0`).
- Provides dynamic dropdowns for **Project Scoping** (`#104`, `#108`, `ALL`) to enforce OQ-06 data isolation.
- Provides dynamic dropdowns for **Jurisdiction** (`IN-KA`, `US-CA`, `GLOBAL`).
- Real-time backend connectivity badge querying `GET /health` (`API Online` / `API Offline` / `Demo Mode`).
- Instant toggle button for Demonstration Mode.

### 4.2 QueryInput (`components/QueryInput.tsx`)
- Multi-line textarea with keyboard shortcut support (<kbd>Enter</kbd> to submit, <kbd>Shift+Enter</kbd> for newline).
- Expandable **Filters Tray** allowing users to restrict retrieval by:
  - `project_id`
  - `jurisdiction`
  - `doc_types` (`code`, `spec`, `report`, `safety_manual`, `drawing_note`, `addendum`)
  - `include_superseded` toggle (for historical auditing).
- Reset and clear controls.

### 4.3 AnswerSection (`components/AnswerSection.tsx`)
- Displays grounded response with status indicators:
  - `COMPLIANT / GROUNDED` (Emerald)
  - `REGULATORY CONFLICT FLAGGED` (Amber)
  - `EVIDENCE INSUFFICIENT / ABSTAINED` (Rose)
- Automatically parses `\[(E\d+)\]` tags into interactive buttons that focus the corresponding citation card and open the Excerpt Inspector.
- One-click copy answer action.

### 4.4 CitationCard (`components/CitationCard.tsx`)
- Displays citation metadata: `[E#]`, document title, version string, document category, section/clause ID, page numbers, and cosine similarity score.
- Clicking the card or the *"Inspect Excerpt"* button displays the verbatim chunk in the inspection pane.

### 4.5 ExcerptViewer (`components/ExcerptViewer.tsx`)
- Displays the exact text extracted by the backend (`text_verbatim`) in a high-contrast mono container.
- Shows structural hierarchy path (`section_path`) and extraction provenance (`native` vs `ocr`, `prose` vs `table`).
- Certified grounding badge confirming that numeric claims and clauses were verified by the 3-stage `CitationValidator`.

### 4.6 ConflictBanner (`components/ConflictBanner.tsx`)
- Accordion-based conflict inspector.
- Compares **Source Document A** vs **Source Document B** side-by-side with exact excerpts and document revisions.
- Displays governing precedence rulings (e.g., explaining why governing technical specifications take legal precedence over historical subcontractor inspection notes).

### 4.7 AbstentionBanner (`components/AbstentionBanner.tsx`)
- Highlights Gate 1, Gate 2, or Gate 3 refusals.
- Explains the exact reason the model refused to answer.
- Guides the engineer to ingest the appropriate governing document or refine search terminology.

## 5. API Integration & Demo Scenarios

### 5.1 Endpoints Utilized
- `GET /health`: Health and version telemetry.
- `POST /query`: Primary natural language retrieval and grounding endpoint.

### 5.2 Demonstration Data Scenarios
Labeled clearly with `[DEMONSTRATION DATA ONLY — NOT REAL REGULATION]`:
1. **Foundation Slab Curing (`supported`):** 14 days curing under high moisture conditions (`[E1]`) and 50 mm reinforcement clear cover (`[E2]`).
2. **Curing Duration Divergence (`conflict_flagged`):** Governing specification v2.0 requires 14 days curing; site inspection report records 7 days curing on site.
3. **Fireproofing Assembly (`abstained`):** Safety refusal because the indexed corpus lacks structural steel fire-resistance ratings.
